# Contributing

Contributions to algorithms, evaluation, performance, tests, and documentation are welcome.

## Before opening a change

1. Read `LICENSE`, `RESPONSIBLE-USE.md`, and `SECURITY.md`.
2. Search existing issues and pull requests.
3. Keep one pull request focused on one problem.
4. Do not include credentials, private game data, production logs, proprietary models, or unlicensed assets.

## Technical changes

- Describe the algorithmic or engineering motivation.
- Add or update tests for behavior changes.
- Record compiler, Python, framework, and hardware assumptions.
- For performance claims, follow `BENCHMARKS.md` and `REPRODUCIBILITY.md`.
- Report regressions and negative results, not only favorable outcomes.
- Avoid changing benchmark opponents or game rules without making that change explicit.

## Documentation

`README.md` is the Simplified Chinese source document. Material changes should be synchronized with `README.en.md` and `README.zh-TW.md`.

## Pull request description

Include the affected components, validation performed, reproducibility information, resource impact, and known limitations. Screenshots and logs must be sanitized.
